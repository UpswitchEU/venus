# Venus working-capital and method-output audit — 3 October 2026

The advisor story audited here is imported annual accounts → valuation request and DCF readiness → method selection and calculation explanation → CSV export. This continues the financial-integrity repairs merged in PR 109.

## Findings and corrections

1. **Manufactured annual working-capital changes.** Partial receivables/inventory/payables were completed with zero; missing cash/current debt were also completed with zero. Differences could span missing years or switch between trade and aggregate definitions. The shared derivation now requires complete comparable components and consecutive actual years, rejects duplicate fiscal periods, uses decimal arithmetic and omits nonfinite outputs. Explicit changes, including zero and negative amounts, take precedence. DCF readiness uses the same derivation and requires evidence for each later period; the earliest year's observation cannot cover a missing later year.
2. **Lost or repaired method bands.** The comparison helper rejected zero/loss endpoints, rounded monetary values and sorted reversed ranges. It now preserves finite published precision, takes a complete pair from one alias family, and suppresses malformed/incoherent ranges. Enterprise and equity bands remain separate.
3. **Mislabelled currencies and bases.** The method table, breakdown cards, sensitivity matrix and stakeholder calculation no longer assume euros. The report currency supplies context unless the method carries its own; unknown currency is disclosed. Each method identifies its value basis. Differences require compatible known currency and basis. Percent differences require a positive baseline. The shareholding calculator requires an equity-valued method.
4. **Unreconciled numeric explanations.** The breakdown previously treated every method value as equity, borrowed global values from another selected method, or substituted enterprise value when equity was absent. Report-level fallbacks now require the same method and compatible currency. Numeric equalities require the earnings product and enterprise-to-equity bridge to reconcile within 0.01 source currency units. Published cards remain available when evidence cannot substantiate the equation.
5. **Lossy financial export and result parsing.** CSV exports preserve the numeric model precision, include currency and value-basis columns, and do not emit unavailable or plan-teaser amounts. The old EUR-specific column names are deliberately replaced with `currency`, `value_basis`, `value`, `range_low`, and `range_high`. Any external scripts consuming the former headers need to update. Machine result readers accept decimal transport syntax rather than interpreting dots as thousands separators.

## Financial methodology

The aggregate working-capital bridge is `(current assets − cash) − (current liabilities − current debt)`; the supported trade bridge is `receivables + inventory − payables`. Neither may fill missing components with zero or be differenced against the other definition. These are supported approximations, not a claim that the schema captures every operating asset/liability, marketable security, acquisition, FX or noncash balance-sheet movement. An advisor's explicit annual change remains authoritative. [Damodaran's working-capital discussion](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/noncashwc.htm) explains the exclusion of cash and interest-bearing financing and the effect of signed changes on cash flow. This implementation does not assert IFRS/IVS certification.

## Verification and release boundary

Initial counterexamples reproduced 18 failures out of 21 cases. The first corrected six-file batch passed 56 tests; the expanded 12-file focused batch passed 101 tests before the final additional DCF fallback case. New tests cover complete/missing balances, zeroes, losses, year gaps, duplicate periods, definition changes, overflow, submitted-request parity, signed/decimal method ranges, incompatible comparisons, native currencies, unavailable results, and equation reconciliation. Final focused and exact-source full CI receipts are saved in `outputs/venus-input-reconciliation-2026-10-03` outside the repository; only successful required checks permit merge. No guard, security audit, or debt allowance is weakened.

This is a Venus correctness repair on the existing backend contracts. No production deployment, database migration, customer-data mutation or authenticated production save/export journey is performed. Backend assessment rollout, all-accounting-source reconciliation, broader manual monetary interfaces and independent SME transaction-outcome calibration remain separate work. Previously documented development/build dependency advisories are not patched by this change. Passing software tests cannot establish perfect valuation accuracy.
